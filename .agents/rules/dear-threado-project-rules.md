# DearThreado — Project Authority Rules

## 1. Source of Truth

The locked DearThreado Master Project Specification and Master Antigravity Implementation Specification are the authoritative sources of truth for this project.

The supplied visual reference assets and finalized DearThreado logo are authoritative for the approved visual direction and brand assets.

## 2. No Independent Product Decisions

Do not independently invent, add, remove, replace, redesign, simplify, or reinterpret any:

- feature
- business rule
- user flow
- navigation
- page
- component behavior
- authentication behavior
- order behavior
- admin capability
- customization behavior
- database requirement
- API requirement
- visual identity
- branding element

unless explicitly required by the locked specifications.

If an implementation choice is necessary, choose the simplest technically appropriate implementation that preserves the locked requirements.

## 3. DearThreado Brand Identity

Preserve the locked DearThreado identity:

- Warm
- Creative
- Playful
- Personal
- Heartfelt
- Premium-cute

The website must feel like a meaningful handmade-gifting experience, not a generic ecommerce template.

The thread concept is an important DearThreado visual language and must be used thoughtfully where specified.

Do not turn the website into an excessive decoration-heavy craft interface.

## 4. Visual References

Use the supplied screenshots as visual-direction references.

Preserve their:

- visual feeling
- spacing character
- typography hierarchy
- rounded-card language
- soft lavender/warm-white atmosphere
- purple-centered identity
- subtle decorative effects
- gentle animations

Do not replace the approved visual direction with a generic ecommerce design.

The supplied final logo must be used as provided.

Do not redesign or regenerate the logo.

## 5. Functional Authority

Written project specifications have priority for functional behavior.

Do not infer that a common ecommerce feature is required merely because other ecommerce websites commonly have it.

Do not add features such as wishlist, deals, unnecessary navigation items, online payment, or other functionality unless explicitly specified.

## 6. Scope Discipline

Implement the complete approved DearThreado project.

Do not expand the project scope.

Do not remove required functionality to simplify implementation.

Do not create fake functionality merely to make an incomplete feature appear finished.

## 7. Technical Quality

Implementation must be integrated and functional.

Verify:

- imports and exports
- routing
- API communication
- database communication
- authentication
- authorization
- validation
- order calculations
- status transitions
- error handling
- responsive behavior
- production build

Run appropriate checks and fix implementation errors before considering the implementation complete.

## 8. Error Handling

When an implementation error occurs, diagnose and fix it rather than silently bypassing the requirement.

Do not weaken a locked business rule simply because it is technically inconvenient.

Do not stop the overall implementation because of a normal fixable implementation error.

## 9. Git

Use Git checkpoints during implementation where appropriate.

A checkpoint must not unnecessarily interrupt or terminate the implementation workflow.

Existing work must be preserved.

Do not reset or discard completed work without explicit authorization.

## 10. Existing Specifications Must Be Read First

Before implementation, read and understand:

1. MASTER_PROJECT_SPECIFICATION
2. MASTER_ANTIGRAVITY_IMPLEMENTATION_SPECIFICATION
3. supplied visual references
4. supplied DearThreado logo

Do not begin implementation based only on this rules file.

## 11. Conflict Resolution

If information appears ambiguous:

1. Check the Master Project Specification.
2. Check the Master Antigravity Implementation Specification.
3. Check the supplied visual references for visual-direction questions.
4. Preserve the already locked project decision.
5. Do not invent a new product decision.

## 12. Completion Principle

The goal is not merely to generate source code.

The goal is to produce the approved DearThreado project according to the locked specifications, with its intended emotional identity, user experience, business rules, technical integration, and visual language preserved.

DearThreado is a project about connection, meaningful gifting, handmade uniqueness, personalization, and creating special moments.

Implementation must preserve that intent.
